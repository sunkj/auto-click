## 2. 系统架构设计

### 2.1 整体架构

采用**Electron主进程 + React渲染进程 + bridge子进程**分离架构：

| 进程 | 职责 | 技术栈 |
| :--- | :--- | :--- |
| **主进程** | 窗口管理、数据库操作、脚本管理、脚本执行引擎、ADB设备管理、IPC协调 | Node.js + TypeORM |
| **渲染进程** | UI渲染、用户交互、状态管理、TinyH264解码投屏 | React + shadcn/ui + Zustand |
| **bridge子进程** | scrcpy-server启动、H264视频流读取推送 | Node.js ESM (bridge.mjs) |

**通信方式**：Electron IPC（主进程 ↔ 渲染进程） + 标准输入输出（主进程 ↔ bridge子进程）

### 2.2 模块划分（实际实现）

| 模块 | 位置 | 职责 |
| :--- | :--- | :--- |
| **脚本管理模块** | 主进程 + 渲染进程 | 脚本/文件夹CRUD、导入导出、IPC注册 |
| **步骤列表模块** | 渲染进程 | 步骤展示、增删改查、单步/全部执行、高亮 |
| **投屏模块** | 渲染进程 + 主进程 + bridge子进程 | 设备连接、画面解码显示、触摸模拟 |
| **脚本引擎模块** | 主进程 | 脚本加载、步骤调度、ADB命令执行、进度推送 |
| **AI解析模块(ai-agent)** | 主进程 | LangGraph子图，意图解析→步骤转换（只解析不执行） |
| **AI编排模块(ai-assistant)** | 主进程 | 协调parse graph+step executor，处理IPC和结果推送 |
| **配置管理** | 主进程 | JSON配置文件读写 |
| **存储模块** | 主进程 | TypeORM + SQLite数据库操作 |

## 5. 模块详细设计（实际实现）

### 5.1 App.tsx - 应用根组件

- **双模式切换**：通过 `panelsVisible` 状态控制左侧面板（ScriptPanel + StepPanel）的显示/隐藏
- **LandingPage模式**（`panelsVisible=false`）：仅显示 MirrorPanel 全屏，适用于未连接设备时的初始页面
- **三栏编辑模式**（`panelsVisible=true`）：显示 ScriptPanel + StepPanel + MirrorPanel
- 应用启动时自动调用 `loadScripts()` 加载脚本数据

| 子组件 | 功能描述 |

**交互说明**：
- 点击文件夹 → 切换展开/收起
- 点击脚本Card → 选中，StepPanel刷新

- 导入/导出 → IPC调用主进程文件对话框

### 5.3 StepPanel - 步骤栏（340px固定宽度）

| 子组件 | 功能描述 |

### 5.4 MirrorPanel + ScreenCanvas - 投屏区域（flex-1自适应）

- 顶部工具栏：收起侧边栏 / 最小化投屏 / 连接信息(USB/Wi-Fi/分辨率) / 连接/断开/返回/Home按钮 / 鼠标坐标显示
- 内容区：遮盖层（LandingPage） + 底层ScreenCanvas
- 底部：连接状态显示（MirrorPanel组件底部）

**ScreenCanvas**（独立组件）：
- 管理TinyH264Decoder解码器实例

- 自动检测视频分辨率，等比缩放显示
- 支持点击、滑动交互（Canvas坐标 → 设备物理坐标映射）
- 拖拽滑动：记录拖拽起止坐标，乘以3倍距离系数发送swipe命令

**窗口最小化**：支持最小化窗口至仅投屏区域（328px宽度），还原时恢复原始窗口尺寸

**连接过渡动效**：连接成功后有3秒过渡动画，从"正在连接..."转为投屏画面（opacity渐出）

## 7. 数据模型设计（实际实现）

### 7.1 ScriptEntity（脚本实体）

| 字段 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | TEXT | PRIMARY KEY | UUID |
| `name` | TEXT | NOT NULL | 脚本/文件夹名称 |
| `type` | TEXT | NOT NULL, DEFAULT 'script' | 'folder' 或 'script' |
| `parentId` | TEXT | NULLABLE | 所属文件夹ID（null为根目录） |
| `filePath` | TEXT | NULLABLE | 脚本文件路径（文件夹为null） |
| `description` | TEXT | NULLABLE | 描述 |
| `sortOrder` | INTEGER | NOT NULL, DEFAULT 0 | 排序字段 |
| `createdAt` | INTEGER | NOT NULL | 创建时间戳 |
| `updatedAt` | INTEGER | NOT NULL | 更新时间戳 |

### 7.2 StepEntity（步骤实体）

| 字段 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 自增主键 |
| `scriptId` | TEXT | NOT NULL, FOREIGN KEY | 所属脚本ID |
| `stepIndex` | INTEGER | NOT NULL | 步骤序号（从1开始） |
| `type` | TEXT | NOT NULL | click / type / swipe / longpress / script / home / openApp / ai |
| `name` | TEXT | NULLABLE | 步骤名称 |

| `updatedAt` | INTEGER | NOT NULL | 更新时间戳 |

**约束**：同一脚本内步骤序号唯一 `UNIQUE(script_id, step_index)`，外键 ON DELETE CASCADE

**步骤类型JSON数据格式**：

| 类型 | data结构 |
| :--- | :--- |
| click | `{ x: number, y: number, description?: string, _condition?: StepCondition, _context?: StepContextOutput }` |
| type | `{ content: string, description?: string, _condition?, _context? }` |
| swipe | `{ direction: 'up'\|'down'\|'left'\|'right', duration: number, description?: string, _condition?, _context? }` |
| longpress | `{ x: number, y: number, duration: number, description?: string, _condition?, _context? }` |
| home | `{ description?: string, _condition?, _context? }` |
| openApp | `{ appName: string, description?: string, _condition?, _context? }` |
| ai | `{ description?: string, _condition?, _context? }` |

### 7.4 Context 数据结构

```typescript
/** 前置条件 */
interface StepCondition {
  key: string
  value: string           // 比较值，支持 {{模板}}
  onMatch: 'skip' | 'stop'
}

/** Context 写入 */
interface StepContextOutput {
  key: string
  value: string           // 支持 {{模板}}
}
```

### 7.5 模板解析规则

步骤执行前，扫描 data 中所有字符串值，将 `{{key}}` 替换为 `context[key]`：

```
data: { x: "{{posX}}", y: "{{posY}}", content: "Hello {{name}}" }
context: { posX: "320", posY: "580", name: "张三" }
解析后: { x: "320", y: "580", content: "Hello 张三" }
```

### 7.6 执行流程（含 Context）

```
1. 解析模板：将 step.data 中所有字符串替换 {{key}} 为 context[key]
2. 检查前置条件（_condition）：
   - 如果 context[_condition.key] === _condition.value
     → onMatch='skip'：跳过当前步骤
     → onMatch='stop'：停止整个脚本
   - 否则 → 正常执行
3. 执行步骤（click/type/swipe/longpress/home/openApp/ai/script）
4. 写入 Context（_context）：context[_context.key] = _context.value
```

### 7.3 前端 Step 接口

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | string | 步骤ID（字符串化） |
| index | number | 步骤序号 |
| type | 'click' \| 'type' \| 'swipe' \| 'longpress' \| 'home' \| 'openApp' \| 'ai' | 步骤类型 |
| params | Record\<string, string\> | 步骤参数字典 |
| description | string | 描述 |
| name | string | 步骤名称 |

## 8. 关键流程设计（实际实现）

### 8.1 应用启动流程

1. Electron主进程启动，初始化数据库连接
2. 加载预加载脚本，暴露IPC API
3. 创建BrowserWindow，加载React应用
4. React应用初始化Zustand Stores
5. scriptStore调用`loadScripts()`，通过IPC获取脚本列表
6. UI渲染三栏布局，底部状态栏显示未连接状态

### 8.2 设备连接与投屏流程

1. 用户点击“连接设备”按钮
2. deviceStore调用`connectDevice()` IPC
3. 主进程执行ADB扫描：`adb devices`
4. 找到设备后，建立连接，获取设备信息（分辨率、型号等）
5. 启动屏幕流服务（方案：`adb exec-out screencap -p` 或 minicap）
6. 通过`event:device-status`推送连接成功事件
7. 渲染进程更新isConnected状态，投屏区域开始接收并渲染画面帧
8. 底部状态栏显示CONNECTED和设备名称

### 8.3 脚本执行与步骤高亮流程

1. 用户选择脚本，点击“运行”按钮
2. 渲染进程发送`script:run` IPC（携带scriptId）
3. 主进程ScriptEngine加载脚本文件，解析steps数组
4. 循环遍历steps，依次执行：
   - 执行前发送`event:step-progress`（status: 'start', stepIndex）
   - 渲染进程更新executingStepIndex，高亮对应步骤
   - 根据步骤类型调用DeviceManager对应ADB命令
   - 执行完成后发送`event:step-progress`（status: 'end', stepIndex）
5. 所有步骤执行完毕，发送`event:script-complete`
6. 渲染进程清除executingStepIndex，显示完成通知

### 8.4 步骤编辑流程

1. 用户点击步骤表格中的某一行，选中步骤
2. scriptStore更新selectedStepIndex
3. 步骤列表下方显示操作行（编辑、删除、运行）
4. 点击“编辑”按钮：
   - 打开Dialog弹窗
   - 使用shadcn/ui的Form组件，预填当前步骤参数
   - 用户修改参数后提交
   - 更新scriptStore中的currentSteps数组
   - 调用`steps:update` IPC，持久化到数据库和脚本文件
5. 点击“删除”按钮：
   - 弹出AlertDialog确认
   - 确认后从currentSteps数组中删除
   - 重新排序剩余步骤的index
   - 调用`steps:update` IPC持久化

## 10. 异常处理设计（实际实现）

| 异常场景 | 处理方式 |
| :--- | :--- |
| 设备未连接时执行脚本 | 引擎检查serial为空，返回 `{ success: false, error: '设备未连接' }` |
| 设备连接失败 | deviceStore状态设为error，显示错误消息 |
| 脚本文件格式错误 | ScriptValidator校验，抛出ScriptEngineError |
| 脚本执行中设备断开 | 步骤执行失败，引擎推送stepError事件后中断 |
| 步骤编辑时数据校验失败 | 前端表单空值检查 |
| ADB命令执行超时 | adb-executor设置10秒timeout，超时抛出异常 |
| 脚本执行超时 | 引擎检查scriptTimeout，超时自动终止 |
| 步骤执行失败重试 | 引擎内循环maxRetries次重试 |
