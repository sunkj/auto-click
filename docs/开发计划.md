## 1. 迭代总览

采用**单功能单迭代**的开发模式，每个迭代完成一个独立可验证的功能模块，迭代周期为 3-7 天。

| 迭代 | 功能模块 | 预计工时 | 交付物 | 依赖 |
| :--- | :--- | :--- | :--- | :--- |
| Iteration 1 ✅ | 项目初始化与环境搭建 | 4h | 可运行的空应用 | 无 |
| Iteration 2 ✅ | 基础框架与布局 | 6h | 三栏布局界面 | Iteration 1 |
| Iteration 3 ✅ | 脚本管理 - 列表展示 | 6h | 脚本列表显示（含 service 层） | Iteration 2 |
| Iteration 4 ✅ | 脚本管理 - 导入/导出 | 8h | 脚本导入导出功能 | Iteration 3 |
| Iteration 5 ✅ | 步骤列表 - 展示与选中 | 6h | 步骤列表显示 | Iteration 3 |
| Iteration 6 ✅ | 步骤编辑 - 编辑/删除 | 8h | 步骤增删改功能 | Iteration 5 |
| Iteration 7 ✅ | 设备连接管理 | 3h | ADB连接设备 | Iteration 2 |
| Iteration 8 ✅ | 投屏画面显示 | 4h | 实时投屏 | Iteration 7 |
| Iteration 9 ✅ | 投屏交互操作 | 2h | 点击/滑动/返回 | Iteration 8 |
| Iteration 10 | 脚本执行引擎 | 12h | 脚本解析与执行 | Iteration 5, Iteration 7 |
| Iteration 11 | 步骤高亮与进度反馈 | 6h | 执行时步骤高亮 | Iteration 10 |
| Iteration 12 | 单步执行功能 | 4h | 单独执行某步骤 | Iteration 10 |
| Iteration 13 | 深色主题与样式优化 | 4h | 完整深色主题 | Iteration 2 |
| Iteration 14 | 集成测试与Bug修复 | 6h | 稳定可用版本 | 所有迭代 |

### Iteration 4：脚本管理 - 导入/导出 ✅

| 项目 | 内容 |
| :--- | :--- |
| **目标** | 实现脚本导入导出功能 |
| **预计工时** | 8小时 → 2小时 |
| **优先级** | P1（重要） |
| **状态** | **已完成** (2026-06-14) |

**任务清单**：
- [x] 实现存储模块（SQLite初始化）— 由 Iteration 3 service 层覆盖
- [x] 实现导入功能（文件对话框 → 读取 .js 文件 → 解析 JSON → 入库）
- [x] 实现导出功能（选中脚本 → 保存对话框 → 写入 .js 文件）
- [x] 列表自动刷新（导入后自动 loadScripts）
- [x] 导入格式校验（JSON 格式校验 + 文件类型过滤）
- [x] 导入文件格式：`// comment\n[{type, data}, ...]`

**实现说明**：
- 导入：`script:import` IPC → `dialog.showOpenDialog` → 读取文件 → 解析 JSON → `createScript` + `addStep` 循环入库
- 导出：`script:export` IPC → `getScriptById` + `getStepsByScriptId` → `dialog.showSaveDialog` → 写入格式化的 `.js` 文件
- 导出按钮在未选中脚本时 disabled
- 支持的导入格式：首行为 `//` 注释的 JSON 数组文件

**验收标准**：
- ✅ 可从本地导入`.js`脚本文件
- ✅ 导入后脚本列表自动更新
- ✅ 可导出选中脚本到指定位置
- ✅ 文件格式校验 + 错误提示
- ✅ 重复导入时提示或覆盖

### Iteration 8：投屏画面显示 ✅

| 项目 | 内容 |
| :--- | :--- |
| **目标** | 实时显示手机屏幕画面 |
| **预计工时** | 12小时 → 4小时 |
| **优先级** | P1（重要） |
| **状态** | **已完成** (2026-06-14) |

**任务清单**：
- [x] 确定投屏方案（@yume-chan/scrcpy + TinyH264 解码）
- [x] 实现主进程 scrcpy 会话管理（AdbScrcpyClient）
- [x] 实现视频流读取 → IPC 帧事件推送
- [x] Canvas 渲染（MirrorPanel 画布组件）
- [x] 处理连接/断开时的画面切换
- [x] 画布自适应缩放

**实现说明**：
- 主进程启动 ScrcpyServer，通过 AdbScrcpyClient.videoStream 读取 H264 帧
- 视频帧通过 IPC（scrcpy:frame）发送到渲染进程
- 渲染进程 MirrorPanel 使用 Canvas 显示
- scrcpy-server.jar 通过 fetch-scrcpy-server 自动获取后推送到设备

**验收标准**：
- ✅ 连接设备后 scrcpy 会话启动
- ✅ 视频帧通过 IPC 推送到渲染进程

## 5. 风险与应对

| 风险项 | 概率 | 影响 | 应对措施 |
| :--- | :--- | :--- | :--- |
| ADB兼容性问题 | 中 | 高 | 提前验证多设备/多Android版本，准备降级方案 |
| 投屏延迟过高 | 中 | 中 | 调研多种方案（minicap/scrcpy协议），选用最优 |
| 脚本沙箱安全漏洞 | 低 | 高 | 使用成熟的vm2，严格限制权限 |
| Electron打包跨平台问题 | 中 | 中 | 提前测试Windows/macOS环境，配置CI |
| 开发时间超出预期 | 中 | 中 | 优先保证P0功能，P2功能可延后 |

## 6. 开发顺序建议

**建议按以下顺序执行：**

1. **第一阶段（基础底座）**：Iteration 1 → 2
2. **第二阶段（脚本核心）**：Iteration 3 → 5 → 6
3. **第三阶段（设备投屏）**：Iteration 7 → 8 → 9（可与第二阶段并行）
4. **第四阶段（执行引擎）**：Iteration 10 → 11 → 12
5. **第五阶段（完善发布）**：Iteration 4 → 13 → 14

**并行开发建议**：
- 完成Iteration 2后，可分配2人分别进行 Iteration 3（脚本）和 Iteration 7（设备）
- 完成Iteration 5后，可分配2人分别进行 Iteration 6（步骤编辑）和 Iteration 8（投屏）
