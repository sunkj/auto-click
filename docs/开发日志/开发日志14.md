## 1. 屏幕文本检测步骤 checkText

**需求：** 添加一个新的节点步骤，识别图像里面是否包含某个文本，包含步骤名称和文本内容。

→ 新增 `checkText` 步骤类型（第9种），执行时自动截图 → VLM 检测文本是否存在 → 匹配时写入上下文。

### 1.1 检测结果写入方式调整

**需求：** 不要自动写入 checkText_result，应该是检测成功时由用户选择某个 Key 并设值。

→ 取消自动写入固定 key，改为「匹配成功时写入上下文」区域让用户配置 Key/Value。

### 1.2 上下文去重

**需求：** 匹配成功时写入上下文，跟下面通用写入上下文重复了，去掉上面那个，描述显示在上面。

→ 移除 checkText 内嵌的匹配写入区域，改为提示文字指引用户使用底部通用「写入上下文」功能。

### 1.3 执行字段名错误

**需求：** 执行报错：检测文本不能为空，日志显示 `data.checkText` 但实际存的是 `data.text`。

→ 修复：`data.checkText` → `data.text`。

## 3. AI 模型配置抽象化

**需求：** 可以切换不同的模型，不要固定 DeepSeek 或智谱。两种角色：一种意图解析，一种视觉分析。

→ 设计方案：配置结构从 `deepseek`+`zhipu` 改为 `llm`（意图解析）+ `vlm`（视觉分析）；服务文件 rename；UI Tab 从 DeepSeek/智谱 改为 意图解析模型/视觉分析模型；旧配置自动迁移。

### 3.1 VLM max_tokens 错误

**需求：** VLM API 错误 400，max_tokens 参数非法 [1,2048]。

→ 旧代码硬编码 `max_tokens: 100`，新代码用了配置默认值 2048 导致超上下文窗口。修复：VLM 调用时 `Math.min(cfg.maxTokens, 200)` + 默认值降为 200。

## 5. AI 工作流 tap 无坐标时不结束

**需求：** 发送「点击钱包」，AI 工作流一直没有结束，日志显示「点击缺少坐标，跳过」。

→ 原因：`step-converter` 无录制坐标时直接跳过 `tap`，生成 0 个步骤。修复：在 `executeAiWorkflow` 中加 VLM 兜底逻辑——0 steps + tap 时截图 + VLM 定位元素生成坐标。

### 5.1 Y 轴坐标少一半

**需求：** 返回坐标 Y 轴少一半，是模型计算的问题吗？

→ 分析：VLM 内部可能对图片做二次缩放，直接返回像素坐标会偏差。改用归一化坐标（0~1），再用设备分辨率还原。

### 5.2 VLM 兜底重构

**需求：** 重构 VLM 兜底逻辑，用 step 里面的 visionClick。

→ 将 `executeAiWorkflow` 中的 VLM 定位逻辑移入 `executeVisionClick()` 统一处理，workflow 直接生成 `visionClick` 步骤。
