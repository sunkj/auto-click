## 1. 等待步骤 Wait

→ 新增第 11 种步骤类型 `wait`，执行时通过 `setTimeout` 延时指定时长。

### 1.2 问题记录

- **步骤类型不支持**：`ScriptValidator` 中有硬编码白名单，漏掉了 `wait` → 修复：追加 `'wait'`

## 2. 定时任务 Scheduler

**需求：** 为已创建的脚本配置定时执行，支持按小时、分钟、天三种周期模式。

→ 完整前后端实现：SchedulerEngine 调度核心 + ScheduleDialog UI + 状态栏指示 + 总开关。

### 2.1 架构设计

```
config.json (schedules + schedulerEnabled)
         │
    SchedulerEngine
         │
    ├── start() / stop() / setEnabled()
    ├── create() / update() / remove() / toggle()
    ├── registerTimer() / removeTimer()
    ├── calculateDelay() — minute / hour / day
    └── onScheduleTrigger()
              ├── 检查总开关
              ├── 检查设备连接 (ctrl.getSerial())
              ├── 检查脚本冲突 (getStatus().isExecuting)
              ├── 执行脚本 (runFullScript)
              └── scheduleNext() — 注册下一轮
```

### 2.4 问题记录

- **执行错乱：选中第二个脚本却执行了第一个**
  - 原因：调度器独立创建 `ScriptEngine` 实例，与主引擎不共享执行状态
  - 修复：通过 `setScriptEngine()` 注入主引擎实例，共享同一个执行队列

- **定时任务跳过：无已连接设备**
  - 原因：`SchedulerEngine` 自己维护 `connectedSerial`，但无人调用 `setSerial()`
  - 修复：改用 `ctrl.getSerial()` 从投屏模块实时获取设备 serial

- **多条定时任务并发执行导致状态错乱**
  - 原因：多个定时器回调同时进入 `onScheduleTrigger`，无并发控制
  - 修复：添加 `executing` 执行锁，忙时跳过本次

- **`updateStatus` 同时写入互相覆盖**
  - 原因：两个定时任务完成时间接近时，`loadConfig()` 读取旧数据后 `saveConfig()` 覆盖对方写入
  - 修复：`updateStatus` 每次重新 `loadConfig()` 读取最新配置

- **底部状态栏不显示**
  - 原因：`SchedulerStatusIndicator` 挂载时未调用 `loadSchedules()`
  - 修复：添加 `useEffect` 自动加载

### 3.1 打包问题

- **图标偏大**：图标内容占满 1024×1024 画布无内边距 → 修复：添加 10% 内边距 + 圆角遮罩
- **`better-sqlite3` 加载失败**（"not a mach-o file"）：打包 Windows 时将原生模块重编译为 PE 格式 → 修复：`npm run postinstall`
- **`better-sqlite3` NODE_MODULE_VERSION 不匹配**：系统 Node.js 137 vs Electron 125 → 修复：`npx electron-rebuild -f -w better-sqlite3`
