## 5. 发现 VLM 坐标不准

> 现在AI助手工作流 没有执行命令了
> （追问后）有执行到了，只是坐标不对，请忽略
> 是不是坐标映射有问题啊，已经找到微信图标，在屏幕底部 Dock 栏（第二行）的第二个位置找到了微信图标，为什么坐标就是不对，而且X轴是对的，Y轴少了一半

VLM（智谱 GLM-4V）返回的 Y 坐标映射到设备分辨率后正好少了一半。调查发现智谱对图片做了内部降采样，导致返回的像素坐标不准。

**改动：** 将 VLM 提示词改为要求返回**百分比坐标（0~1）**，映射时直接乘以设备分辨率，绕过模型内部分辨率问题。

## 10. UI Automator 在 ColorOS 上受限

> UI automator dump 读不到应用里面的节点吗？比如 微信聊天列表
> 我手动解锁了，请继续

在 ColorOS（OPPO/OnePlus）设备上，`accessibility_enabled` 被系统保护，无法通过 ADB 修改，导致 `uiautomator dump` 对微信等第三方应用返回空节点树（`bounds="[0,0][0,0]"`）。

**当前状态：** UI Automator 在系统界面可用，第三方应用内部受限。需要用户手动在手机上开启无障碍服务，或考虑混合方案（UI Automator + VLM 回退）。

## 11. 坐标映射修复（百分比 → 原始坐标）

> 显示执行完成，但是并没有点击到微信
> （日志显示 UI Automator 返回坐标 (417, 2149)，映射后变成 (450360, 5037256)）

旧映射逻辑将 UI Automator 的 `bounds` 属性值先按百分比除以 `width`，再用 `calibrateCoordinates` 乘回分辨率，导致坐标爆炸（`2149 / 1 * 2340 ≈ 503万`）。

**改动：** UI Automator 节点直接传 `scaleX=1, scaleY=1`，把原始像素坐标透传给 step-converter。

## 14. UI Automator 在第三方应用受限

> UI automator dump 读不到应用里面的节点吗？比如 微信聊天列表

ColorOS（OPPO/OnePlus）上 `settings put secure accessibility_enabled` 被系统保护，`uiautomator dump` 对第三方应用返回空节点树。

**结论：** 当前方案组合：
- **系统界面 / 桌面：** UI Automator 可用
- **第三方应用内部：** UI Automator 失效
- **待实现：** VLM 视觉分析作为 fallback，或引导用户在手机上开启无障碍服务
