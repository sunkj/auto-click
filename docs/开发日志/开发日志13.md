## 1. 图像识别点击步骤 visionClick

**需求：** 准备用图像识别点击功能作为一个新的 step 类型。

### 1.1 背景

AI 智能操控的 `tap` 动作在无录制坐标时，已通过 VLM 兜底实现了「截图 → 识别元素位置 → 点击」的流程（详见 execute-ai-workflow.ts 的 VLM 兜底逻辑）。现在需要将这个能力封装为独立的脚本步骤类型。

### 1.2 需求要点

- 新增 `visionClick` 步骤类型（第10种步骤类型）
- 参数：目标文本/元素描述（target）
- 执行时自动截图 → 调用 VLM 定位元素（归一化坐标）→ 还原为设备坐标 → ADB tap

### 1.3 设计决策

| 决策项 | 选择 | 原因 |
| :--- | :--- | :--- |
| 步骤类型命名 | `visionClick`（camelCase） | 与现有 StepType 命名风格一致 |
| 坐标系统 | 归一化坐标 (0~1) × 设备分辨率 | 避免 VLM 内部图片处理导致坐标系偏差 |
| VLM 提示 | 返回归一化坐标 JSON | 与 execute-ai-workflow 兜底逻辑一致 |
