## 1. 屏幕文本检测步骤 checkText

**需求：** 添加一个新的节点步骤。识别图像里面是否包含某个文本，大概包含一个节点名称、一个文本内容。

### 1.1 背景

现有的 AI 智能操控模块已通过 `check_text` AI 动作类型支持屏幕文本检测（F-26），但该能力仅限 AI Agent 内部使用，无法作为独立的脚本步骤嵌入流程中。用户需要一种**可编排的、可视化的**文本检测步骤。

### 1.2 需求要点

- 新增 `checkText` 步骤类型（第9种步骤类型）
- 参数：步骤名称（节点名称）+ 目标文本（文本内容）+ 匹配成功时写入上下文的 Key/Value
- 执行时自动截图 → 调用智谱 GLM-4V 视觉模型检测 → 返回匹配结果
- 不自动写入 Context，由用户配置"匹配成功时写入"的 Key 和 Value
- 支持与前置条件联动，实现条件分支

### 1.3 设计决策

| **决策项** | **选择** | **原因** |
| :--- | :--- | :--- |
| 步骤类型命名 | `checkText`（camelCase） | 与现有 StepType 命名风格一致 |
| 文本检测引擎 | 智谱 GLM-4V（HTTP API） | 复用 ai-agent 模块现有 `checkScreenText` 工具函数 |
| 截图方式 | `adb exec-out screencap -p` | 复用 ai-agent 模块现有截图服务 |
| Context 写入方式 | 用户配置 `matchedContext.key` + `matchedContext.value` | 不自动写固定 key，由用户决定匹配成功时写什么值 |
| AI 动作映射 | `check_text` → `checkText` EngineStep | 与 AI Agent 的 check_text 动作对应，AI 也能产出 checkText 步骤 |
