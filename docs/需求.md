## 1. 项目背景与目标

### 1.1 背景

随着移动端应用自动化需求的增长，测试人员、开发者和普通用户需要在PC端对手机进行远程控制，并通过脚本实现自动化操作（如自动化测试、游戏挂机、日常任务自动化等）。

### 1.2 目标

开发一款跨平台的手机投屏管理软件，支持 **Windows 与 macOS**，实现低延迟投屏、键鼠模拟交互、强大的脚本录制与管理功能，并通过机器人通知将运行结果同步至团队协作软件。

## 2. 产品范围 (V1.0)

- **平台支持**：Windows 10/11 (x64) 与 macOS 11+ (Intel/Apple Silicon)
- **移动端**：Android 10+ (基于ADB协议)
- **连接方式**：USB连接（优先），无线Wi-Fi连接（后续支持）
- **设备数量**：单设备连接

## 3. 功能性需求

### 3.1 设备连接与投屏

软件需要能够识别并显示连接的手机屏幕。

| **ID** | **功能名称** | **详细描述** |
| :--- | :--- | :--- |
| **F-01** | 设备发现 | 自动检测通过USB连接的Android设备，若未安装ADB驱动需给出下载引导（Windows需引导驱动，macOS通常无需额外驱动） |
| **F-02** | 画面投屏 | 将手机画面实时投射到PC端窗口中，支持窗口缩放，延迟<100ms |
| **F-03** | 设备信息 | 状态栏显示设备型号、分辨率、电量、是否开启开发者模式等状态 |

### 3.2 鼠标键鼠模拟交互

鼠标操作应模拟真实手指触摸Android屏幕的效果。

| **ID** | **功能名称** | **详细描述** |
| :--- | :--- | :--- |
| **F-04** | 鼠标点击 | 单击=手指点击，双击=双击，右键应支持模拟“返回”或自定义功能 |
| **F-05** | 滑动与拖动 | 支持鼠标按住拖动模拟手指滑动（如翻页）；支持选中文件或图标进行长按拖动 |
| **F-06** | 文字输入 | 支持PC键盘输入，并将文本直接传输到手机输入框中。需解决中英文输入法切换冲突 |

### 3.3 脚本引擎 (核心)

系统需内置JavaScript脚本引擎，通过JS调用SDK控制手机。

| **ID** | **功能名称** | **详细描述** |
| :--- | :--- | :--- |
| **F-07** | API开放 | 暴露`click(x,y)`、`swipe(x1,y1,x2,y2,duration)`、`setText(text)`等API |
| **F-08** | 脚本执行 | 支持加载`.js`文件并执行，执行过程中实时高亮显示代码行，日志输出至控制台 |
| **F-09** | 绑定元素 | 支持查找坐标、图片匹配（找图）、颜色匹配（找色）等高级API |

### 3.4 录制与脚本生成

通过录制用户操作自动生成脚本，降低编写门槛。

| **ID** | **功能名称** | **详细描述** |
| :--- | :--- | :--- |
| **F-10** | 操作录制 | 点击“录制”按钮后，记录用户的鼠标点击、滑动、输入操作，自动生成时间轴和代码 |
| **F-11** | 手动微调 | 在生成的脚本中，支持手动编辑JSON或JS代码；支持设置延迟（Sleep）；支持点击坐标随机扩散（防检测） |

### 3.5 脚本管理与任务调度

对脚本进行分类和定时执行。

| **ID** | **功能名称** | **详细描述** |
| :--- | :--- | :--- |
| **F-12** | 脚本分组 | 支持创建文件夹（如“游戏类”、“工作类”），支持脚本拖拽移动 |
| **F-13** | 导入导出 | 支持本地导入`.js`脚本，支持导出脚本压缩包，支持上传至云端服务器（可选） |
| **F-14** | 定时任务 | 设置Cron表达式，在指定时间点执行脚本；支持设置循环次数（如执行10次）或无限循环直到手动停止 |

### 3.6 消息通知与机器人

打通第三方即时聊天工具，实现监控报警。

| **ID** | **功能名称** | **详细描述** |
| :--- | :--- | :--- |
| **F-15** | Webhook配置 | 支持配置飞书/钉钉/微信企业版自定义机器人的Webhook地址 |
| **F-16** | 事件通知 | 脚本开始时发送“开始运行”通知，脚本结束时发送“运行结束/成功”通知 |
| **F-17** | 异常报警 | 脚本运行报错（如找不到图片）或设备断开连接时，发送红色报警通知，附携带错截图 |

## 4. 非功能性需求

| **ID** | **类别** | **要求描述** |
| :--- | :--- | :--- |
| **N-01** | 性能 | CPU占用率空闲<5%，投屏时<15%；显存占用<500MB |
| **N-02** | 兼容性 | 支持1920x1080及以上主流分辨率，兼容华为、小米、三星、OPPO、vivo等主流品牌 |
| **N-03** | 跨平台一致性 | Windows与macOS版本核心功能完全一致，配置文件和脚本格式互通 |
| **N-04** | 安全性 | 脚本存储需加密（防止源码泄露）；ADB连接仅限本地，不得私自上传用户手机文件 |

## 5. 附录：技术实现建议

### 5.1 核心技术选型建议

- **投屏核心**：使用 **scrcpy** (v4.0+) 作为底层服务。其本身支持Windows和macOS双平台，可大幅降低跨平台开发成本。
- **交互控制**：利用 scrcpy 的 `--hid-mouse` 和 `--hid-keyboard` 参数实现HID模拟。此模式将电脑鼠标模拟为“物理外挂”，兼容性最佳。
- **脚本引擎**：使用 **微软的 ClearScript** (V8引擎) 或 **Node.js** 嵌入式版本来运行JavaScript。
- **跨平台UI框架**：
  - **Qt (C++)**：scrcpy原生基于Qt，集成度高，资源占用低，推荐使用。
  - **Electron (Web技术)**：开发效率高但内存占用较高，macOS上体验尚可。
  - **Flutter**：桌面端支持正在成熟，也可考虑。

### 5.2 跨平台注意事项

- **ADB工具路径**：Windows使用`adb.exe`，macOS使用`adb`（需处理权限`chmod +x`）。软件需自动识别操作系统并调用对应可执行文件。
- **USB权限**：macOS无需驱动但可能需要用户授权“屏幕录制”权限才能捕获输入；Windows需要正确的ADB驱动。
- **窗口管理**：双平台窗口API不同，使用Qt可统一抽象层。

### 5.3 难点攻克与参考

1. **坐标适配问题**
   - 手机分辨率与PC窗口分辨率不同。脚本录制的坐标必须是 **相对坐标**（例如 `0.5, 0.5` 代表屏幕中心），执行时再根据当前设备分辨率换算为绝对坐标，否则换手机后脚本会失效。

2. **即时通讯机器人格式差异**
   - 虽然都叫Webhook，但飞书、钉钉、微信的JSON结构完全不同。
   - *建议*：开发一个 **“通知适配层”** 。用户选择“飞书”后，软件自动套用对应的MsgType模板，仅需用户填写密钥。

3. **连接稳定性**
   - ADB连接容易因手机锁屏、USB线松动断开。
   - *建议*：实现 **守护进程**。通过读取 `adb devices` 状态，发现设备离线自动重连（`adb reconnect`），确保无人值守的自动化任务能够7x24小时运行。
