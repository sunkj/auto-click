## 1. 概述

### 1.1 设计目标
为 AutoClick 设计投屏管理服务层，基于 adb 命令行工具 + `@yume-chan/scrcpy` 生态实现 Android 设备的屏幕镜像与远程控制功能。

### 1.2 服务定位
- **运行环境**：Electron 主进程（Node.js）+ bridge子进程（ESM）+ 渲染进程（Canvas渲染）
- **服务名称**：`screen-mirror/`

## 2. 实际技术选型

| 依赖包 | 版本 | 说明 | 使用方式 |
| :--- | :--- | :--- | :--- |
| adb命令行 | 系统PATH | 设备发现、信息获取、触摸控制 | child_process.exec 异步执行 |
| `@yume-chan/adb` | ^2.6.0 | ADB协议核心（bridge子进程使用） | bridge.mjs中引用 |
| `@yume-chan/adb-scrcpy` | ^2.3.2 | Scrcpy集成层（bridge子进程使用） | bridge.mjs中引用 |
| `@yume-chan/adb-server-node-tcp` | ^2.5.2 | TCP连接ADB Server | bridge.mjs中引用 |
| `@yume-chan/fetch-scrcpy-server` | ^1.0.0 | 自动获取scrcpy-server.jar | bridge.mjs中引用 |
| `@yume-chan/scrcpy` | ^2.3.0 | Scrcpy协议核心 | bridge.mjs中引用 |
| `@yume-chan/scrcpy-decoder-tinyh264` | ^2.1.0 | H264软件解码器 | ScreenCanvas渲染端使用 |

### 核心设计决策

| 决策项 | 选择 | 原因 |
| :--- | :--- | :--- |
| ADB设备发现 | `adb devices -l` 命令行解析 | 避免@yume-chan/adb ESM兼容问题 |
| 触摸控制 | `adb shell input` 命令行 | 独立于scrcpy控制通道，更稳定 |
| 视频流 | bridge.mjs子进程读取→IPC推送→渲染端TinyH264解码 | 绕过ESM模块require限制 |
| 屏幕渲染 | Canvas + TinyH264Decoder软件解码 | Electron兼容性优于WebCodecs硬解码 |

## 5. 模块详细设计（实际实现）

### 5.1 ADB辅助模块（adb.ts）

| 属性 | 说明 |
| :--- | :--- |
| **文件位置** | `src/main/screen-mirror/adb.ts` |
| **职责** | 通过 adb 命令行工具执行设备发现、信息获取 |
| **依赖** | `child_process.exec` |

**核心方法**：

| 方法 | 参数 | 返回值 | 说明 |
| :--- | :--- | :--- | :--- |
| `getDevices()` | 无 | `Promise<SimpleDeviceInfo[]>` | 执行`adb devices -l`，解析输出 |
| `getDeviceModel(serial)` | serial | `Promise<string>` | `adb shell getprop ro.product.model` |
| `getDeviceResolution(serial)` | serial | `Promise<{width,height}>` | `adb shell wm size` 正则解析 |
| `exec(args)` | args字符串 | `Promise<string>` | 通用adb命令执行（5s超时） |
| `shell(serial, cmd)` | serial, cmd | `Promise<string>` | 设备shell命令执行 |

**ADB路径自动检测**：优先检查常见路径（`/usr/local/bin/adb`等），回退使用 `which adb`，缓存结果

---

### 5.2 桥接进程管理（bridge-manager.ts）

| 属性 | 说明 |
| :--- | :--- |
| **文件位置** | `src/main/screen-mirror/bridge-manager.ts` |
| **职责** | 管理bridge.mjs子进程的生命周期 |
| **依赖** | `child_process.fork` |

**核心方法**：

| 方法 | 参数 | 说明 |
| :--- | :--- | :--- |
| `start(serial)` | 设备序列号 | fork bridge.mjs，传递设备序列号 |
| `stop()` | 无 | 发送SIGTERM终止子进程 |

**通信方式**：
- 主进程 → 子进程：通过`child.send()` 发送设备serial
- 子进程 → 主进程：通过`process.send()` 推送视频帧数据
- 主进程 → 渲染进程：通过IPC `scrcpy:frame` 转发

---

### 5.3 桥接子进程（bridge.mjs）

| 属性 | 说明 |
| :--- | :--- |
| **文件位置** | `src/main/screen-mirror/bridge.mjs` |
| **职责** | 独立ESM进程，启动scrcpy-server并读取H264视频流 |
| **依赖** | @yume-chan全链路（adb/adb-server-node-tcp/adb-scrcpy/scrcpy） |

**工作流程**：
1. 通过`@yume-chan/adb-server-node-tcp`连接ADB Server（127.0.0.1:5037）
2. 使用`@yume-chan/adb-scrcpy`的`AdbScrcpyClient`启动scrcpy-server
3. 订阅videoStream，读取H264帧
4. 通过`process.send()` 将帧数据（config/frame类型）推送回主进程

**注意**：使用 `.mjs` 扩展名以支持ESM模块导入，解决 `@yume-chan` 包无法通过 `require()` 加载的问题

---

### 5.4 控制处理器（control.ts）

| 属性 | 说明 |
| :--- | :--- |
| **文件位置** | `src/main/screen-mirror/control.ts` |
| **职责** | 通过 `adb shell` 命令发送触控和按键指令 |
| **依赖** | adb.ts 的 shell 方法 |

**核心方法**：

| 方法 | 命令 | 说明 |
| :--- | :--- | :--- |
| `tap(x, y)` | `input tap x y` | 模拟点击 |
| `swipe(x1,y1,x2,y2,dur?)` | `input swipe x1 y1 x2 y2 duration` | 模拟滑动 |
| `type(text)` | `input text escaped_text` | 输入文字（不支持中文） |
| `back()` | `input keyevent 4` | 返回键 |
| `home()` | `input keyevent 3` | Home键 |

**状态管理**：内部维护 `deviceSerial` 变量，通过 `setSerial/getSerial` 访问

---

### 5.5 渲染端 ScreenCanvas（ScreenCanvas.tsx）

| 属性 | 说明 |
| :--- | :--- |
| **文件位置** | `src/renderer/src/components/ScreenCanvas.tsx` |
| **职责** | 管理TinyH264Decoder实例，接收IPC帧，渲染到Canvas，处理交互 |

**核心逻辑**：

| 功能 | 实现方式 |
| :--- | :--- |
| 视频流接收 | IPC `scrcpy:frame` → ReadableStream → `pipeTo(decoder.writable)` |
| H264解码 | `TinyH264Decoder({ canvas })` → 解码后直接渲染到Canvas |
| 分辨率检测 | 优先从meta消息获取，否则从canvas.width/height读取 |
| 显示尺寸计算 | `calcDisplaySize()` 等比缩放，`Math.min(container/视频, 1)` |
| 点击交互 | Canvas点击 → CSS坐标 → `(x * 视频宽/CSS宽, y * 视频高/CSS高)` → adb shell tap |
| 滑动交互 | mousedown→mousemove→mouseup 记录拖拽轨迹，×3倍距离发送swipe |
| 最小化模式 | 全屏无工具栏，高度用window.innerHeight，全尺寸显示 |

**坐标映射公式**：
```
物理X = 鼠标X * (视频宽度 / CSS显示宽度)
物理Y = 鼠标Y * (视频高度 / CSS显示高度)
```

## 6. 连接与交互流程（实际实现）

### 6.1 设备连接流程

1. 用户点击"连接"按钮 → `deviceStore.connect()`
2. 渲染进程 IPC `scrcpy:connect` → 主进程
3. 主进程 `adb.getDevices()` 扫描USB设备
4. 找到设备 → `ctrl.setSerial(serial)` + `adb.getDeviceModel()` + `adb.getDeviceResolution()`
5. `bridge.start(serial)` → fork bridge.mjs 子进程
6. bridge.mjs 连接ADB Server、启动scrcpy-server、开始读取视频流
7. 主进程返回 `{ serial, model, resolution, deviceWidth, deviceHeight, transport }`
8. 渲染进程 deviceStore 更新 status='connected' + deviceInfo
9. MirrorPanel 进入3秒过渡动画 → 渐出显示投屏画面

### 6.2 视频流推送流程

1. bridge.mjs 读取到H264帧（config/frame）
2. 通过 `process.send()` 发送到主进程
3. 主进程通过 `BrowserWindow.webContents.send('scrcpy:frame', payload)` 推送到渲染进程
4. 渲染进程 ScreenCanvas 的 IPC listener 接收帧
5. config帧 → `controller.enqueue({ type: 'configuration', data })`
6. frame帧 → `controller.enqueue({ type: 'data', data, keyframe, pts })`
7. ReadableStream → pipeTo → TinyH264Decoder 解码 → Canvas渲染

### 6.3 断开流程

1. 用户点击"断开"按钮 → `deviceStore.disconnect()`
2. 渲染进程 IPC `scrcpy:disconnect` → 主进程
3. `bridge.stop()` → kill bridge子进程
4. `ctrl.setSerial(null)` 重置设备状态
5. 返回 `{ success: true }`
6. deviceStore 更新 status='idle', deviceInfo=null
7. MirrorPanel 显示 LandingPage 遮盖层

## 7. 与V1.0设计差异

| V1.0设计 | V2.0实际实现 |
| :--- | :--- |
| AdbManager独立类 | 简化为adb.ts命令行封装 |
| ServerFileManager独立类 | bridge.mjs内部处理scrcpy-server |
| ScrcpyClient独立类 | bridge.mjs内部管理 |
| VideoDecoder独立类 | ScreenCanvas内联TinyH264Decoder |
| ControlHandler含丰富API | control.ts仅tap/swipe/back/home/type |
| 独立types.ts文件 | 类型定义在channels.ts中 |
| `ScrcpyOptions` | Scrcpy 启动选项 |
| `DecoderOptions` | 解码器配置选项 |
| `DecoderStats` | 解码统计信息 |
| `ControlCommand` | 控制指令类型 |
| `ErrorCode` | 错误代码枚举 |
