## 1. 模块概述

### 1.1 模块定位

脚本执行引擎是AutoClick的核心模块，负责加载用户脚本、解析步骤、调度执行、通过ADB命令控制设备，并实时反馈执行状态。

### 1.2 职责边界

| 职责 | 说明 |
| :--- | :--- |
| **脚本加载** | 通过ScriptService从数据库加载脚本实体和步骤列表 |
| **步骤调度** | 按顺序执行步骤，支持全量执行（runFullScript）和单步执行（runSingleStep） |
| **命令执行** | 通过adb-executor独立模块直接调用`adb shell`命令 |
| **状态推送** | 通过IPC（engine:stepStart/stepEnd/stepError/complete）推送执行进度 |
| **错误处理** | 捕获执行异常，支持重试机制和超时控制 |

| 不包含的职责 | 说明 |
| :--- | :--- |
| ADB设备连接管理 | 由screen-mirror模块负责，引擎通过serial参数引用 |
| 脚本数据持久化 | 由ScriptService负责 |
| UI高亮渲染 | 由渲染进程Zustand store监听IPC事件更新 |
| 与投屏模块耦合 | 引擎完全不依赖screen-mirror，独立运行 |

### 1.3 架构决策

- **与投屏解耦**：不依赖 screen-mirror 模块，通过渲染进程传递的 `serial` 设备标识，使用 `adb-executor.ts` 独立执行 ADB shell 命令
- **主进程执行**：不创建独立子进程，直接在 Electron 主进程中执行步骤调度
- **配置驱动**：通过 config.ts 读取超时时间、步骤间隔、重试次数等配置

## 2. 目录结构（实际实现）

```
src/main/
├── script-engine/                 # 脚本执行引擎模块
│   ├── index.ts                   # 模块入口 + IPC Handler注册
│   ├── script-engine.ts           # 核心引擎类
│   ├── script-loader.ts           # 脚本加载器（从ScriptService加载）
│   ├── script-validator.ts        # 脚本校验器
│   ├── step-executor.ts           # 步骤执行器
│   ├── execution-queue.ts         # 执行队列管理器（FIFO）
│   ├── execution-context.ts       # 执行上下文工厂
│   ├── adb-executor.ts            # ADB命令执行器（独立模块）
│   ├── types.ts                   # 类型定义
│   └── errors.ts                  # 错误码枚举和自定义错误类
```

### 2.1 文件职责说明（实际实现）

| 文件 | 职责 | 依赖 |
| :--- | :--- | :--- |
| `index.ts` | 注册IPC处理器 (`engine:run/runStep/stop/getStatus`) | script-engine |
| `script-engine.ts` | 核心引擎，协调加载→校验→执行→推送全流程 | script-loader, validator, step-executor, queue |
| `script-loader.ts` | 通过ScriptService从DB加载脚本实体→转换为EngineStep[] | ScriptService (外部) |
| `script-validator.ts` | 校验步骤类型/参数合法性 | types |
| `step-executor.ts` | 执行单个步骤，调用adb-executor | adb-executor |
| `execution-queue.ts` | FIFO队列管理，处理并发请求和停止 | types |
| `execution-context.ts` | 创建执行上下文（executionId/startTime等） | types |
| `adb-executor.ts` | 通过child_process执行adb命令（独立于screen-mirror） | child_process |
| `types.ts` | TypeScript类型定义 | 无 |
| `errors.ts` | 错误码枚举和ScriptEngineError类 | 无 |

```
index.ts (IPC Handler)
    │
    ▼
script-engine.ts
    │
    ├── script-loader.ts ──→ ScriptService (外部: ../script/services/script-service)
    ├── script-validator.ts
    ├── step-executor.ts ──→ adb-executor.ts (内部独立)
```

### 3.1 外部依赖说明

| 外部模块 | 调用方式 | 说明 |
| :--- | :--- | :--- |
| `ScriptService` | 构造函数注入 | 通过scriptId获取脚本实体和步骤列表 |

| `BrowserWindow` | Electron API | 向所有窗口推送执行进度事件 |

## 4. 核心流程设计

### 4.1 脚本执行整体流程

用户点击运行
↓
渲染进程发送 script:run IPC
↓
ScriptEngine.runFullScript(scriptId)
↓
ExecutionQueue.enqueue() 加入队列
↓
执行队列调度
↓
ScriptLoader.load(scriptId)
↓
从文件系统读取.js文件
↓
ScriptValidator.validate(scriptObj)
↓
校验步骤格式合法性
↓
遍历steps，依次执行 StepExecutor.execute()
↓
每个步骤前通过ipc发送 step-start 事件
↓
StepExecutor调用 DeviceManager 对应方法
↓
等待执行结果（成功/失败）
↓
每个步骤后通过ipc发送 step-end 事件
↓
所有步骤完成后通过ipc发送 script-complete 事件


### 4.2 步骤执行详细流程

StepExecutor.execute(step, context)
↓
根据 step.type 分支处理
↓
┌─────────────┬─────────────┬─────────────┐
│ click │ type │ swipe │
↓ ↓ ↓
解析x,y坐标 解析text内容 解析方向/时长
↓ ↓ ↓
调用tap(x,y) 调用inputText 调用swipe()
等待响应 等待响应 等待响应
└─────────────┴─────────────┴─────────────┘
↓
处理步骤后延迟（delay / stepInterval）
↓
返回执行结果（成功/失败）


### 4.3 错误处理流程

步骤执行中发生错误
↓
捕获异常（ADB超时/设备断开/格式错误）
↓
ExecutionQueue.stopCurrent()
↓
清空队列中的等待任务
↓
通过ipc发送 step-error 事件（携带错误信息）
↓
通过ipc发送 script-error 事件
↓
渲染进程显示错误Toast

## 9. 滑动坐标计算规则

### 9.1 方向到坐标的映射

根据设备屏幕分辨率，将滑动方向转换为起止坐标。

| 方向 | 起点 | 终点 | 说明 |
| :--- | :--- | :--- | :--- |
| up | (width/2, height × 0.8) | (width/2, height × 0.2) | 从下向上滑动 |
| down | (width/2, height × 0.2) | (width/2, height × 0.8) | 从上向下滑动 |
| left | (width × 0.8, height/2) | (width × 0.2, height/2) | 从右向左滑动 |
| right | (width × 0.2, height/2) | (width × 0.8, height/2) | 从左向右滑动 |

### 9.2 自定义滑动距离

如果配置了 `distance` 参数，按指定距离滑动；否则滑动半屏。

| 方向 | 有distance时的计算 |
| :--- | :--- |
| up | 终点Y = 起点Y - distance |
| down | 终点Y = 起点Y + distance |
| left | 终点X = 起点X - distance |
| right | 终点X = 起点X + distance |

**边界保护**：计算后的坐标不能超出屏幕范围（0 ~ width/height）

## 10. 延迟与等待机制

### 10.1 等待类型

| 等待类型 | 配置方式 | 优先级 | 说明 |
| :--- | :--- | :--- | :--- |
| 步骤级延迟 | 步骤中的 `delay` 字段 | 最高 | 执行完当前步骤后等待指定毫秒 |
| 全局间隔 | 脚本中的 `stepInterval` 字段 | 中 | 每个步骤之间的固定间隔 |
| 无等待 | 两者都未设置 | 最低 | 步骤间无额外等待 |

### 10.2 延迟执行逻辑


步骤执行完成
↓
判断步骤是否配置了 delay
↓
有 delay ──────────────────────────→ 等待 delay 毫秒
↓ 无
判断脚本是否配置了 stepInterval
↓
有 stepInterval ────────────────────→ 等待 stepInterval 毫秒
↓ 无
立即执行下一步

## 11. 超时控制

| 超时类型 | 默认值 | 说明 |
| :--- | :--- | :--- |
| 单步超时 | 10秒 | 单个ADB命令执行超时 |
| 设备响应超时 | 5秒 | 设备无响应时的等待时间 |

> **说明**：不设脚本总超时限制，脚本执行时长由用户自行控制。

### 11.1 超时后处理

1. 中断当前步骤执行
2. 发送超时错误事件（错误码：E007）
3. 停止后续步骤执行
4. 清理执行状态

## 12. 并发与排队机制

### 12.1 执行队列规则

| 场景 | 行为 |
| :--- | :--- |
| 当前无执行 | 立即开始执行 |
| 当前有执行 | 新请求进入队列FIFO，等待当前执行完成 |
| 执行中停止 | 清空队列，不再执行等待中的任务 |

### 12.2 队列状态

| 状态字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `isRunning` | `boolean` | 是否有任务正在执行 |
| `pendingTasks` | `PendingTask[]` | 等待执行的任务列表 |
| `currentTask` | `PendingTask | null` | 当前执行的任务 |

## 13. 设备断开处理

执行过程中设备断开的处理流程：

设备断开检测（ADB命令失败）
↓
设置 shouldStop = true
↓
清空执行队列
↓
通过ipc发送 step-error 事件（错误码：E005，设备已断开）
↓
通过ipc发送 script-error 事件
↓
清理执行状态
↓
渲染进程显示"设备已断开连接"Toast

## 14. 性能考量

| 考量点 | 优化方案 |
| :--- | :--- |
| 脚本解析 | 首次加载后缓存解析结果，文件未修改时复用缓存 |
| 步骤执行 | 使用异步非阻塞方式，避免UI卡顿 |
| ADB调用 | 复用ADB连接，避免频繁建立连接 |
| 大脚本处理 | 支持分页加载步骤，不在内存中一次性加载全部 |
| 日志写入 | 异步写入日志文件，避免阻塞执行 |
