## 1. 模块概述

### 1.1 模块定位

脚本执行引擎是AutoClick的核心模块，负责加载用户脚本、解析步骤、调度执行、与设备管理器交互，并实时反馈执行状态。

### 1.2 职责边界

| 职责 | 说明 |
| :--- | :--- |
| **脚本加载** | 从文件系统读取.js脚本文件，解析为标准步骤格式 |
| **步骤调度** | 按顺序执行步骤，支持全量执行和单步执行 |
| **命令转换** | 将步骤类型转换为对应的ADB命令调用 |
| **状态推送** | 通过IPC向渲染进程推送执行进度 |
| **错误处理** | 捕获执行异常，中断流程并返回错误信息 |

| 不包含的职责 | 说明 |
| :--- | :--- |
| ADB命令底层实现 | 由DeviceManager模块负责 |
| 脚本文件存储 | 由StorageManager模块负责 |
| UI高亮渲染 | 由渲染进程负责 |

## 4. 核心流程设计

### 4.1 脚本执行整体流程

用户点击运行
↓
渲染进程发送 script:run IPC
↓
ScriptEngine.runFullScript(scriptId)
↓
ExecutionQueue.enqueue() 加入队列
↓
执行队列调度
↓
ScriptLoader.load(scriptId)
↓
从文件系统读取.js文件
↓
ScriptValidator.validate(scriptObj)
↓
校验步骤格式合法性
↓
遍历steps，依次执行 StepExecutor.execute()
↓
每个步骤前通过ipc发送 step-start 事件
↓
StepExecutor调用 DeviceManager 对应方法
↓
等待执行结果（成功/失败）
↓
每个步骤后通过ipc发送 step-end 事件
↓
所有步骤完成后通过ipc发送 script-complete 事件


### 4.2 步骤执行详细流程

StepExecutor.execute(step, context)
↓
根据 step.type 分支处理
↓
┌─────────────┬─────────────┬─────────────┐
│ click │ type │ swipe │
↓ ↓ ↓
解析x,y坐标 解析text内容 解析方向/时长
↓ ↓ ↓
调用tap(x,y) 调用inputText 调用swipe()
等待响应 等待响应 等待响应
└─────────────┴─────────────┴─────────────┘
↓
处理步骤后延迟（delay / stepInterval）
↓
返回执行结果（成功/失败）


### 4.3 错误处理流程

步骤执行中发生错误
↓
捕获异常（ADB超时/设备断开/格式错误）
↓
ExecutionQueue.stopCurrent()
↓
清空队列中的等待任务
↓
通过ipc发送 step-error 事件（携带错误信息）
↓
通过ipc发送 script-error 事件
↓
渲染进程显示错误Toast

## 9. 滑动坐标计算规则

### 9.1 方向到坐标的映射

根据设备屏幕分辨率，将滑动方向转换为起止坐标。

| 方向 | 起点 | 终点 | 说明 |
| :--- | :--- | :--- | :--- |
| up | (width/2, height × 0.8) | (width/2, height × 0.2) | 从下向上滑动 |
| down | (width/2, height × 0.2) | (width/2, height × 0.8) | 从上向下滑动 |
| left | (width × 0.8, height/2) | (width × 0.2, height/2) | 从右向左滑动 |
| right | (width × 0.2, height/2) | (width × 0.8, height/2) | 从左向右滑动 |

### 9.2 自定义滑动距离

如果配置了 `distance` 参数，按指定距离滑动；否则滑动半屏。

| 方向 | 有distance时的计算 |
| :--- | :--- |
| up | 终点Y = 起点Y - distance |
| down | 终点Y = 起点Y + distance |
| left | 终点X = 起点X - distance |
| right | 终点X = 起点X + distance |

**边界保护**：计算后的坐标不能超出屏幕范围（0 ~ width/height）

## 10. 延迟与等待机制

### 10.1 等待类型

| 等待类型 | 配置方式 | 优先级 | 说明 |
| :--- | :--- | :--- | :--- |
| 步骤级延迟 | 步骤中的 `delay` 字段 | 最高 | 执行完当前步骤后等待指定毫秒 |
| 全局间隔 | 脚本中的 `stepInterval` 字段 | 中 | 每个步骤之间的固定间隔 |
| 无等待 | 两者都未设置 | 最低 | 步骤间无额外等待 |

### 10.2 延迟执行逻辑


步骤执行完成
↓
判断步骤是否配置了 delay
↓
有 delay ──────────────────────────→ 等待 delay 毫秒
↓ 无
判断脚本是否配置了 stepInterval
↓
有 stepInterval ────────────────────→ 等待 stepInterval 毫秒
↓ 无
立即执行下一步

## 11. 超时控制

| 超时类型 | 默认值 | 说明 |
| :--- | :--- | :--- |
| 单步超时 | 10秒 | 单个ADB命令执行超时 |
| 设备响应超时 | 5秒 | 设备无响应时的等待时间 |

> **说明**：不设脚本总超时限制，脚本执行时长由用户自行控制。

### 11.1 超时后处理

1. 中断当前步骤执行
2. 发送超时错误事件（错误码：E007）
3. 停止后续步骤执行
4. 清理执行状态

## 12. 并发与排队机制

### 12.1 执行队列规则

| 场景 | 行为 |
| :--- | :--- |
| 当前无执行 | 立即开始执行 |
| 当前有执行 | 新请求进入队列FIFO，等待当前执行完成 |
| 执行中停止 | 清空队列，不再执行等待中的任务 |

### 12.2 队列状态

| 状态字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `isRunning` | `boolean` | 是否有任务正在执行 |
| `pendingTasks` | `PendingTask[]` | 等待执行的任务列表 |
| `currentTask` | `PendingTask | null` | 当前执行的任务 |

## 13. 设备断开处理

执行过程中设备断开的处理流程：

设备断开检测（ADB命令失败）
↓
设置 shouldStop = true
↓
清空执行队列
↓
通过ipc发送 step-error 事件（错误码：E005，设备已断开）
↓
通过ipc发送 script-error 事件
↓
清理执行状态
↓
渲染进程显示"设备已断开连接"Toast

## 14. 性能考量

| 考量点 | 优化方案 |
| :--- | :--- |
| 脚本解析 | 首次加载后缓存解析结果，文件未修改时复用缓存 |
| 步骤执行 | 使用异步非阻塞方式，避免UI卡顿 |
| ADB调用 | 复用ADB连接，避免频繁建立连接 |
| 大脚本处理 | 支持分页加载步骤，不在内存中一次性加载全部 |
| 日志写入 | 异步写入日志文件，避免阻塞执行 |
