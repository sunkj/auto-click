## 1. 概述

定时任务功能允许用户为已创建的脚本配置定时执行，支持按小时、分钟、天三种周期模式。当满足时间条件时，系统自动调用脚本执行引擎运行指定的脚本。

### 1.1 目标

- 用户可为任意脚本创建定时任务
- 支持 **按小时**、**按分钟**、**按天** 三种执行周期
- 定时任务在应用运行时生效，应用关闭时自动暂停
- 提供可视化的任务列表管理（查看、启停、删除）

### 1.2 影响范围

| 模块 | 说明 |
| :--- | :--- |
| **主进程 - Scheduler 模块** | 新增 `src/main/scheduler/` 目录，定时任务核心逻辑 |
| **主进程 - Config** | `AppConfig` 新增 `schedules` 持久化配置 |
| **渲染进程 - UI** | ScriptPanel 底部新增定时任务入口 |
| **渲染进程 - 弹窗** | 新增 `ScheduleDialog.tsx` 定时任务管理弹窗 |
| **Preload** | 新增 `scheduler:*` IPC 通道 |

## 3. 数据模型

### 3.1 ScheduleConfig

存储在 `config.json` 中，与 `AppConfig` 合并。

```typescript
/** 定时任务周期类型 */
export type ScheduleCycle = 'minute' | 'hour' | 'day'

/** 定时任务配置 */
export interface ScheduleConfig {
  id: string               // 唯一标识（UUID）
  scriptId: string         // 关联的脚本 ID
  scriptName: string       // 脚本名称（UI 展示用，冗余存储）
  enabled: boolean         // 是否启用
  cycle: ScheduleCycle     // 周期类型
  /** 分钟级配置（cycle='minute'） */
  minuteInterval?: number  // 间隔分钟数，如 5、10、30
  /** 小时级配置（cycle='hour'） */
  hourInterval?: number    // 间隔小时数，如 1、2、6
  /** 天级配置（cycle='day'） */
  dayTime?: string         // 执行时间 "HH:mm"，如 "08:00"
  lastRunAt?: number       // 上次执行时间戳
  lastStatus?: 'success' | 'skipped' | 'failed'  // 上次执行结果
  lastError?: string       // 上次失败的错误信息（仅 lastStatus='failed' 时有值）
  createdAt: number        // 创建时间
}
```

### 3.2 AppConfig 扩展

```typescript
export interface AppConfig {
  // ... 现有字段
  schedulerEnabled: boolean     // 总开关：是否启用定时任务
  schedules: ScheduleConfig[]  // 定时任务列表
}
```

`schedulerEnabled` 为 `false` 时所有定时任务暂停，`ScheduleDialog` 列表中的个体启停开关依然保留，但受总开关控制。

## 4. 核心调度器设计

### 4.1 SchedulerEngine

新增 `src/main/scheduler/scheduler-engine.ts`，核心调度逻辑：

```typescript
class SchedulerEngine {
  private timers: Map<string, Timer>  // scheduleId → Timer
  private config: AppConfig
  private scriptEngine: ScriptEngine

  /** 启动调度器，遍历所有 enabled 的定时任务，注册定时器 */
  start(): void

  /** 停止所有定时器 */
  stop(): void

  /** 总开关：启用/禁用所有定时任务 */
  setEnabled(enabled: boolean): void

  /** 添加/更新一个定时任务（重启对应的定时器） */
  upsertSchedule(schedule: ScheduleConfig): void

  /** 删除定时任务（取消对应的定时器） */
  removeSchedule(id: string): void

  /** 计算下次执行时间并注册定时器 */
  private registerTimer(schedule: ScheduleConfig): void

  /** 执行定时任务回调 */
  private async onScheduleTrigger(schedule: ScheduleConfig): Promise<void>
}
```

### 4.2 时间计算逻辑

#### 按分钟 (cycle='minute')

```
下次执行 = 当前时间 + minuteInterval × 60 × 1000
```

- 以 **首次注册时间** 为基准，每隔 `minuteInterval` 分钟执行一次
- 例如 `minuteInterval=30`，首次注册在 10:23，则在 10:53、11:23、11:53... 执行
- 应用重启后恢复定时器：检查 `lastRunAt`，计算上次执行后应等待的时间

#### 按小时 (cycle='hour')

```
下次执行 = 当前时间 + hourInterval × 3600 × 1000
```

- 以 **首次注册时间** 为基准，每隔 `hourInterval` 小时执行一次
- 例如 `hourInterval=2`，首次注册在 08:15，则在 10:15、12:15、14:15... 执行
- 应用重启后恢复定时器逻辑同上

#### 按天 (cycle='day')

```
下次执行 = 当天 dayTime 对应的时间戳
如果已超过当天 dayTime → 明天 dayTime
```

- 每日固定时刻执行，不关心首次注册时间
- 例如 `dayTime="08:00"`，则每天 08:00 执行
- 应用重启后检查当天是否已执行过（比对 `lastRunAt` 与当天 `dayTime`）

### 4.3 生命周期

```
应用启动 → loadConfig() 加载 schedules
         → SchedulerEngine.start()
         → 如果 schedulerEnabled=false → 不注册任何定时器
         → 遍历 enabled 的 schedule → 计算下次执行时间 → 注册 setTimeout

应用运行中:
         → 到达执行时间 → onScheduleTrigger()
         → 检查总开关（关闭→跳过）
         → 检查设备连接（无设备→记录 skipped→下一周期）
         → 检查脚本冲突（有冲突→记录 skipped→下一周期）
         → 调用 scriptEngine.runFullScript(scriptId, serial)
         → 更新 lastRunAt + lastStatus（success/failed）
         → 计算下次执行时间 → 注册新一轮 setTimeout

用户操作:
         → 总开关切换 → setEnabled(false) → 停止所有定时器
         →              setEnabled(true)  → 重新注册所有 enabled 的定时器

         → 创建/编辑定时任务 → 调用 upsertSchedule()
         → 保存 config.json
         → 重启对应定时器

         → 暂停定时任务 → 设置 enabled=false
         → 取消对应定时器

         → 删除定时任务 → 调用 removeSchedule()
         → 取消对应定时器
         → 保存 config.json

应用关闭:
         → SchedulerEngine.stop()
         → 清除所有定时器
```

### 4.4 执行前置条件检查

定时器触发时，依次检查以下条件，任一不满足则跳过本次执行：

| 检查项 | 不满足时的行为 |
| :--- | :--- |
| **总开关**：主控开关是否开启 | 所有定时器不注册也不触发 |
| **设备连接**：当前是否有已连接的 Android 设备 | 跳过，记录 `lastStatus='skipped'`，日志 `[Scheduler] ⏭ 跳过: 无设备连接` |
| **脚本执行冲突**：当前是否有其他脚本正在执行 | 跳过，记录 `lastStatus='skipped'`，日志 `[Scheduler] ⏭ 跳过: 已有脚本在运行` |

**前置条件检查逻辑**：

```typescript
async function onScheduleTrigger(schedule: ScheduleConfig) {
  // 0. 检查总开关
  if (!isSchedulerEnabled()) {
    // 总开关关闭，不执行任何定时任务
    return
  }

  // 1. 检查设备连接
  const serial = getConnectedDeviceSerial()
  if (!serial) {
    console.log(`[Scheduler] ⏭ 跳过定时任务 "${schedule.scriptName}": 无已连接设备`)
    updateScheduleStatus(schedule.id, 'skipped')
    scheduleNextRun(schedule)  // 注册下一次
    return
  }

  // 2. 检查是否有脚本正在执行
  if (isScriptRunning()) {
    console.log(`[Scheduler] ⏭ 跳过定时任务 "${schedule.scriptName}": 已有脚本在运行`)
    updateScheduleStatus(schedule.id, 'skipped')
    scheduleNextRun(schedule)
    return
  }

  // 3. 执行脚本
  console.log(`[Scheduler] ▶ 执行定时任务 "${schedule.scriptName}"`)
  try {
    await scriptEngine.runFullScript(schedule.scriptId, serial)
    updateScheduleStatus(schedule.id, 'success')
    console.log(`[Scheduler] ✔ 定时任务 "${schedule.scriptName}" 完成`)
  } catch (err) {
    updateScheduleStatus(schedule.id, 'failed', err.message)
    console.log(`[Scheduler] ✘ 定时任务 "${schedule.scriptName}" 失败: ${err.message}`)
  }

  // 4. 注册下一次执行
  scheduleNextRun(schedule)
}
```

**关键设计**：
- 不设重试逻辑，任何不满足条件的情况都跳过等待下一周期
- `isScriptRunning()` 通过查询 `ScriptEngine.getStatus().isExecuting` 判断
- 每次状态变更通过 `scheduler:statusUpdate` IPC 推送至渲染进程，实时更新 UI 列表和状态栏
- 应用关闭期间错过的多次执行只补最后一次（通过 `lastRunAt` 判断）

### 4.5 总开关与个体开关的关系

| 总开关 `schedulerEnabled` | 个体 `enabled` | 定时器状态 | 是否执行 |
| :--- | :--- | :--- | :--- |
| `true` | `true` | 已注册 | ✅ 到时间执行 |
| `true` | `false` | 未注册 | ❌ 不执行 |
| `false` | `true` | 已暂停（保留配置） | ❌ 不执行 |
| `false` | `false` | 已暂停（保留配置） | ❌ 不执行 |

- **总开关关闭时**：所有定时器被清除，列表中个体按钮可操作但受总开关影响不执行
- **总开关开启时**：遍历所有 `enabled=true` 的任务重新注册定时器
- 切换总开关不影响个体的 `enabled` 值

## 5. IPC 通道设计

新增 `scheduler:*` IPC 通道：

| 通道 | 方向 | 参数 | 返回 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `scheduler:list` | renderer → main | — | `ScheduleConfig[]` | 获取所有定时任务 |
| `scheduler:create` | renderer → main | `{ scriptId, scriptName, cycle, minuteInterval?, hourInterval?, dayTime? }` | `ScheduleConfig` | 创建定时任务 |
| `scheduler:update` | renderer → main | `{ id, ...更新字段 }` | `ScheduleConfig` | 更新定时任务（启停、修改参数） |
| `scheduler:delete` | renderer → main | `id: string` | `{ success: boolean }` | 删除定时任务 |
| `scheduler:toggle` | renderer → main | `id: string, enabled: boolean` | `ScheduleConfig` | 启用/暂停单个定时任务 |
| `scheduler:toggleAll` | renderer → main | `enabled: boolean` | `{ enabled: boolean }` | 总开关：启用/禁用所有定时任务 |
| `scheduler:statusUpdate` | main → renderer | `ScheduleConfig` | — | 定时任务状态变更通知（用于实时更新 UI 列表和状态栏） |

## 7. 持久化方案

定时任务配置存储在 `config.json` 的 `schedules` 数组中，与应用配置共用同一个文件：

```
userData/
├── config.json          # 应用配置 + 定时任务列表
└── AutoClick.sqlite     # 脚本/步骤数据
```

**优点**：
- 无需新建数据库表
- config.ts 已有完整的读写逻辑
- 配置变更后自动保存

**缺点**：
- 不适合大量数据（定时任务通常很少，可忽略）

## 8. 设备依赖处理

定时任务执行时依赖已连接的 Android 设备。

**当前约束**：
- 当前应用仅支持单设备连接
- 如果添加了多设备支持（不在本次范围），定时任务需要指定 serial

**执行逻辑**：

```typescript
async function onScheduleTrigger(schedule: ScheduleConfig) {
  const serial = getConnectedDeviceSerial()  // 从 deviceStore 或主进程获取
  if (!serial) {
    console.log(`[Scheduler] ⏭ 跳过定时任务 "${schedule.scriptName}": 无已连接设备`)
    return  // 跳过，等待下一周期
  }
  await scriptEngine.runFullScript(schedule.scriptId, serial)
  updateLastRun(schedule.id, Date.now())
}
```

## 11. 备选方案

### 方案 A：node-cron（不使用）
引入 `node-cron` 库可以实现标准的 Cron 表达式，但：
- 需要额外依赖
- Cron 语法对用户不友好
- 用户需求只需要三种简单周期，不必用完整的 Cron

### 方案 B：setInterval（不使用）
直接用 `setInterval` 定期检查时间：
- 无法精确到每天固定时刻
- 应用长时间运行可能有累积误差

### ✅ 方案 C：setTimeout 链式调度（选用）
每次执行完成后计算下次时间并注册 `setTimeout`：
- 精确可控
- 支持任意复杂的时间计算
- 应用关闭时所有定时器自然清除，重启时重新注册
