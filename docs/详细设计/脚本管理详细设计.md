# AutoClick - 服务层设计：脚本管理 Service（技术实现版）

---

## 1. 概述

### 1.1 设计目标
为 AutoClick 设计脚本管理服务层，负责脚本及其步骤数据的持久化存储与操作管理，与前端 UI 层解耦，提供统一的数据访问接口。

### 1.2 服务定位
- **运行环境**：Electron 主进程（Node.js）
- **服务名称**：`ScriptService`

---

## 2. 技术选型

### 2.1 ORM 框架选型

选用 **TypeORM** 作为 ORM 框架。

**选择理由**：
- 官方支持 Electron 平台
- 装饰器语法与 TypeScript 深度集成
- 同时支持 Active Record 和 Data Mapper 两种模式
- 内置完善的迁移工具
- 社区活跃，生态成熟

### 2.2 依赖包清单

| 依赖包 | 版本 | 说明 |
| :--- | :--- | :--- |
| `typeorm` | ^0.3.20 | ORM 核心框架 |
| `sqlite3` | ^5.1.7 | SQLite3 驱动 |
| `reflect-metadata` | ^0.2.2 | TypeORM 装饰器依赖 |

### 2.3 备选方案说明

| 备选方案 | 适用场景 | 不选用的原因 |
| :--- | :--- | :--- |
| better-sqlite3 + 手写 SQL | 极简项目，表结构稳定 | 需手写所有 SQL，维护成本高 |
| Drizzle ORM | 需要渲染进程直接调用 | 需额外配置 Proxy，复杂度增加 |
| Prisma | 大型项目，需要强大的类型生成 | Electron 兼容性需额外配置，引擎较重 |

## 4. 实体设计

### 4.1 脚本实体（ScriptEntity）

| 字段 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | TEXT | PRIMARY KEY | UUID |
| `name` | TEXT | NOT NULL | 脚本名称 |
| `file_path` | TEXT | NOT NULL, UNIQUE | 脚本文件绝对路径 |
| `description` | TEXT | | 脚本描述 |
| `sort_order` | INTEGER | NOT NULL, DEFAULT 0 | 排序字段 |
| `created_at` | INTEGER | NOT NULL | 创建时间戳 |
| `updated_at` | INTEGER | NOT NULL | 更新时间戳 |
| `steps` | OneToMany | | 关联的步骤列表 |

### 4.2 步骤实体（StepEntity）

| 字段 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 自增主键 |
| `script_id` | TEXT | NOT NULL, FOREIGN KEY | 所属脚本ID |
| `step_index` | INTEGER | NOT NULL | 步骤序号 |
| `type` | TEXT | NOT NULL | click / type / swipe / script / longpress / home / openApp / ai / checkText |
| `data` | TEXT | NOT NULL | 步骤参数（JSON字符串） |
| `created_at` | INTEGER | NOT NULL | 创建时间戳 |
| `updated_at` | INTEGER | NOT NULL | 更新时间戳 |
| `script` | ManyToOne | ON DELETE CASCADE | 关联的脚本 |

**约束**：同一脚本内步骤序号唯一 `UNIQUE(script_id, step_index)`

### 4.3 步骤类型数据格式

| 类型 | 数据结构 |
| :--- | :--- |
| click | `{ x: number, y: number, description?: string }` |
| type | `{ content: string, description?: string }` |
| swipe | `{ direction: 'up'|'down'|'left'|'right', duration: number, description?: string }` |
| script | `{ scriptName: string, description?: string }` |
| longpress | `{ x: number, y: number, duration: number, description?: string }` |
| home | `{ description?: string }` |
| ai | `{ description: string }` |
| checkText | `{ text: string, description?: string }` |

## 5. 数据源配置

### 5.1 配置说明

- **数据库类型**：SQLite
- **数据库路径**：`app.getPath('userData')/database.sqlite`
- **同步模式**：`synchronize: false`（生产环境使用迁移）
- **日志级别**：`['error', 'warn']`
- **实体目录**：`src/main/database/entities/**/*.ts`
- **迁移目录**：`src/main/database/migrations/**/*.ts`

### 5.2 初始化流程

- Electron 主进程启动时调用 `initializeDatabase()`
- 检查数据库连接状态，如未初始化则执行连接
- 自动运行待执行的迁移文件

## 6. 仓储层设计（Repository Pattern）

### 6.1 脚本仓储（ScriptRepository）

| 方法 | 说明 |
| :--- | :--- |
| `create(data)` | 创建脚本记录 |
| `findById(id)` | 根据ID查询脚本 |
| `findAll()` | 查询所有脚本（按 sort_order 排序） |
| `update(id, updates)` | 更新脚本信息 |
| `delete(id)` | 删除脚本 |
| `updateOrder(scriptIds)` | 批量更新脚本排序 |
| `getMaxSortOrder()` | 获取当前最大排序值 |

### 6.2 步骤仓储（StepRepository）

| 方法 | 说明 |
| :--- | :--- |
| `create(data)` | 创建步骤记录 |
| `findById(id)` | 根据ID查询步骤 |
| `findByScriptId(scriptId)` | 查询脚本的所有步骤（按 step_index 排序） |
| `update(id, updates)` | 更新步骤信息 |
| `delete(id)` | 删除步骤 |
| `deleteByScriptId(scriptId)` | 删除脚本的所有步骤 |
| `getMaxStepIndex(scriptId)` | 获取脚本的最大步骤序号 |
| `shiftStepIndices(scriptId, fromIndex, offset)` | 批量调整步骤序号 |

## 7. 服务层设计（ScriptService）

### 7.1 脚本操作接口

| 方法 | 参数 | 返回值 | 说明 |
| :--- | :--- | :--- | :--- |
| `createScript` | name, filePath, description?, sortOrder? | ScriptEntity | 创建新脚本 |
| `getAllScripts` | 无 | ScriptEntity[] | 获取所有脚本 |
| `getScriptById` | id | ScriptEntity \| null | 根据ID获取脚本 |
| `updateScript` | id, updates | ScriptEntity \| null | 更新脚本信息 |
| `deleteScript` | id | boolean | 删除脚本及关联步骤 |
| `updateScriptsOrder` | scriptIds | void | 批量调整脚本顺序 |

### 7.2 步骤操作接口

| 方法 | 参数 | 返回值 | 说明 |
| :--- | :--- | :--- | :--- |
| `addStep` | scriptId, stepData, insertIndex? | StepEntity | 添加步骤 |
| `getStepsByScriptId` | scriptId | StepEntity[] | 获取脚本的所有步骤 |
| `updateStep` | stepId, stepData | StepEntity \| null | 更新步骤 |
| `deleteStep` | stepId | boolean | 删除步骤 |
| `replaceSteps` | scriptId, steps | StepEntity[] | 全量替换步骤列表 |
| `updateStepsOrder` | scriptId, stepIds | void | 批量调整步骤顺序 |

### 7.3 文件同步接口

| 方法 | 参数 | 返回值 | 说明 |
| :--- | :--- | :--- | :--- |
| `syncToFile` | scriptId | boolean | 将步骤数据同步到脚本文件 |
| `loadFromFile` | filePath | `{ script, steps }` | 从文件加载脚本并入库 |

## 9. 注意事项

### 9.1 Electron 环境特殊处理

| 注意点 | 说明 |
| :--- | :--- |
| **原生模块编译** | SQLite3 安装后需运行 `electron-rebuild` 重新编译 |
| **数据库路径** | 使用 `app.getPath('userData')` 确保用户读写权限 |
| **进程隔离** | 数据库操作仅在主进程执行，渲染进程通过 IPC 调用 |

### 9.2 核心逻辑说明

| 场景 | 处理逻辑 |
| :--- | :--- |
| 新增脚本排序 | 未指定 sortOrder 时，自动追加到末尾（当前最大排序值 + 1） |
| 调整脚本顺序 | 根据传入的脚本ID数组顺序，重新设置每个脚本的 sort_order |
| 新增步骤 | 未指定位置时追加到末尾；指定位置时，后续步骤序号 +1 |
| 删除步骤 | 删除后，后续步骤序号 -1，保持连续性 |
| 脚本删除级联 | TypeORM 的 ON DELETE CASCADE 自动删除关联步骤 |
| 文件同步 | 编辑步骤后可选同步回 `.js` 文件，保持数据库与文件一致性 |
