## 1. 架构概述

### 1.1 技术栈（实际实现）

| 层级 | 技术选型 | 说明 |
| :--- | :--- | :--- |
| 桌面容器 | Electron 31 | 跨平台打包（Windows + macOS） |
| UI框架 | React 18 + TypeScript | 用户交互界面 |
| UI组件库 | shadcn/ui (Radix UI + TailwindCSS) | 现代UI组件库，支持深色主题 |
| 样式方案 | TailwindCSS 3.4 | 原子化CSS |
| 状态管理 | Zustand 4 | 轻量级状态管理 |
| 构建工具 | Vite 5 + TypeScript | 渲染进程构建与HMR |
| 脚本引擎 | 主进程内执行（无沙箱） | 基于ScriptService + ADB直接调用 |
| 投屏核心 | @yume-chan/scrcpy + TinyH264 | 视频流采集、解码与Canvas渲染 |
| ADB协议 | @yume-chan/adb + adb命令行 | 设备连接与控制 |
| 通信机制 | ipcMain/ipcRenderer | Electron进程间通信 |
| 数据存储 | SQLite (TypeORM + better-sqlite3) | 本地关系数据库 |
| 打包工具 | electron-builder | 应用打包分发 |

### 1.2 架构原则

- **主进程集中**：核心业务逻辑集中在主进程（Node.js），减少进程间通信开销
- **渲染进程轻量化**：仅负责UI渲染，所有数据操作通过IPC委托主进程
- **独立性**：脚本引擎通过ADB命令行直接执行，与投屏模块解耦
- **跨平台一致**：Windows与macOS使用同一套代码

## 2. 进程架构

### 2.1 实际进程模型

| 进程 | 职责 |
| :--- | :--- |
| **主进程**（Node.js） | 应用生命周期、窗口管理、数据库操作（TypeORM + SQLite）、ADB设备管理、脚本执行引擎、屏幕镜像IPC协调、配置读写 |
| **渲染进程**（Chromium） | React界面渲染、三栏布局展示、投屏画布（Canvas + TinyH264解码）、用户交互响应、Zustand状态管理 |
| **bridge子进程**（Node.js ESM） | 独立子进程，通过IPC与主进程通信，管理scrcpy视频流的读取与推送 |

### 2.2 进程通信架构


## 3. 核心模块设计

### 3.1 脚本管理模块（`src/main/script/`）

- **持久化**：TypeORM + SQLite，实体包括 `ScriptEntity` 和 `StepEntity`
- **服务层**：`ScriptService` 封装所有 CRUD 操作
- **IPC通道**：`script:*` 系列通道，通过 preload 暴露给渲染进程
- **文件夹支持**：脚本支持分组到文件夹（`type: 'folder' | 'script'`），仅支持一级目录
- **导入导出**：支持 `.js` 文件格式的导入导出（首行注释 + JSON数组格式）

### 3.2 脚本执行引擎（`src/main/script-engine/`）

- **运行位置**：主进程直接执行，不创建独立子进程
- **执行方式**：顺序执行步骤队列（FIFO），全量执行与单步执行
- **ADB命令**：通过 `adb-executor.ts` 独立模块直接调用 `adb shell` 命令
- **与投屏解耦**：不依赖 screen-mirror 模块，通过渲染进程传递设备 serial
- **步骤类型**：支持 `click`、`type`、`swipe`、`longpress` 四种
- **进度推送**：通过 IPC 推送 `stepStart/stepEnd/stepError/complete` 事件
- **重试机制**：支持步骤失败重试（最多3次）
- **超时控制**：支持脚本执行超时（默认1800秒）

### 3.3 投屏模块（`src/main/screen-mirror/`）

- **ADB连接**：通过 `adb` 命令行工具执行设备发现、信息获取
- **视频流**：`bridge.mjs` 子进程启动 scrcpy-server，读取 H264 视频流
- **解码与渲染**：渲染进程使用 `TinyH264Decoder` 解码 H264 帧，渲染到 Canvas
- **交互控制**：通过 `adb shell input` 命令发送触摸/按键指令
- **坐标映射**：Canvas坐标 → 设备物理坐标的等比缩放转换
- **窗口最小化**：支持最小化窗口至仅投屏区域大小（328px宽度）

### 3.4 配置管理

- 配置文件存储在 `userData/config.json`
- 配置项：脚本超时时间、步骤执行间隔、最大重试次数
- 通过 `config:load` / `config:save` IPC 通道提供读写

## 5. 技术风险与应对（实际实现）

| 风险 | 状态 | 应对措施 |
| :--- | :--- | :--- |
| 脚本死循环 | ✅ 已处理 | 超时控制（config.scriptTimeout）+ shouldStop 标记 |
| ADB断连 | ⚠️ 未实现守护重连 | 手动点击重连 |
| macOS权限 | ⚠️ 需用户手动授权 | 引导用户授予屏幕录制权限 |
| 不同分辨率坐标失效 | ✅ 已处理 | 执行时动态获取设备分辨率并换算 |
| 中文输入 | ⚠️ 已知限制 | input text 命令不支持中文，待后续解决 |

## 6. V2.0 与 V1.0 设计差异说明

| 项目 | V1.0 设计 | V2.0 实际实现 | 原因 |
| :--- | :--- | :--- | :--- |
| 进程模型 | 5进程（主/UI/核心服务/投屏/脚本） | 2进程（主/渲染）+ bridge子进程 | 简化架构，避免过度设计 |
| 脚本引擎 | 独立子进程 + vm2沙箱 | 主进程直接执行 | 当前步骤基于ADB命令，无JS代码执行风险 |
| 投屏方案 | 独立投屏进程 | 主进程协调 + bridge子进程 | 兼容ESM模块导入限制 |
| 视频解码 | WebCodecs硬解码 | TinyH264软件解码 | Electron环境兼容性 |
| WebSocket | 独立WebSocket通道 | 统一使用IPC通道 | 简化通信架构 |
| 任务调度 | node-schedule定时任务 | 未实现 | V1.0范围外 |
| Webhook通知 | 飞书/钉钉/微信 | 未实现 | V1.0范围外 |
