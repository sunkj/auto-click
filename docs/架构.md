## 1. 架构概述

### 1.1 技术栈

| 层级 | 技术选型 | 说明 |
| :--- | :--- | :--- |
| 桌面容器 | Electron | 跨平台打包（Windows + macOS） |
| UI层 | React | 用户交互界面 |
| 服务层 | Node.js | 核心业务逻辑 |
| 脚本引擎 | 独立子进程 + 沙箱 | 执行用户JS脚本 |
| 投屏核心 | scrcpy | 视频流采集与设备控制 |
| 通信机制 | ipcMain/ipcRenderer | Electron进程间通信 |
| 数据存储 | SQLite | 本地数据库 |

### 1.2 架构原则

- **进程隔离**：核心模块独立运行，单点崩溃不影响整体
- **沙箱安全**：用户脚本在受限环境执行，禁止访问系统资源
- **跨平台一致**：Windows与macOS使用同一套代码

## 2. 多进程架构

### 2.1 进程职责

| 进程 | 职责 |
| :--- | :--- |
| 主进程 | 应用生命周期、子进程管理、系统托盘、窗口管理 |
| UI进程 | React界面渲染、脚本编辑器、投屏画布、日志展示 |
| 核心服务进程 | ADB控制、任务调度、Webhook通知、数据库操作 |
| 投屏进程 | scrcpy管理、视频流订阅、坐标转换、事件注入 |
| 脚本进程 | JS沙箱环境、白名单API执行（动态创建） |

### 2.2 进程异常处理

| 进程 | 异常处理 |
| :--- | :--- |
| 主进程 | 崩溃即退出，记录日志 |
| UI进程 | 主进程自动重启 |
| 核心服务进程 | 主进程自动重启 |
| 投屏进程 | 主进程自动重启 |
| 脚本进程 | 仅影响当前脚本，主进程无影响 |

## 3. 核心模块设计

### 3.1 投屏模块

- 基于scrcpy订阅视频流，实时绘制到Canvas
- 支持鼠标点击、滑动、拖动等操作模拟手指
- 录制时存储相对坐标（0-1），执行时动态转换为当前设备分辨率

### 3.2 脚本引擎模块

- 独立子进程执行，带超时控制（默认30分钟）
- 沙箱环境，仅开放白名单API
- 支持录制用户操作自动生成脚本
- 支持手动微调（延迟、坐标随机扩散等）

### 3.3 任务调度模块

- 基于node-schedule实现定时任务
- 支持Cron表达式、循环次数、无限循环
- 任务排队执行，防止并发冲突

### 3.4 通知模块

- 适配器模式，支持飞书、钉钉、微信机器人
- 统一消息格式，自动转换各平台Webhook
- 脚本运行开始/结束/异常时发送通知，异常时附带截图

## 4. 技术风险与应对

| 风险 | 应对措施 |
| :--- | :--- |
| 脚本死循环 | 独立进程 + 超时强制终止 |
| ADB断连 | 守护进程自动重连 |
| macOS权限 | 引导用户授予屏幕录制权限 |
| 不同分辨率坐标失效 | 统一使用相对坐标 |
